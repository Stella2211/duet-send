# duet-send

自分のパソコンから **Claude Duet** のコーディネーターにメッセージを送るツールです。

コーディネーターはクラウド上の Claude Code セッションとして動いています。Claude Code には `claude -p "メッセージ" --cloud <セッションID>` でクラウドのセッションにメッセージを送る機能がありますが、コーディネーターのセッションIDはときどき変わり、スクリプト側では新しいIDを知る方法がありません。duet-send はその問題を解消します。

- コーディネーターは、自分の今のセッションIDを小さな **ルーティング表**（1行の JSON）として Google ドライブの1つのファイルの **ファイル名** に入れておき、IDが変わるたびにファイル名を変更します。（ファイル名を使うのは、Claude の Google ドライブコネクタがファイル名は変更できても本文は変更できないためです。）
- そのファイルは「リンクを知っている全員」・権限 **閲覧者** で共有します。duet-send は Google にサインインせず、通常の HTTPS でファイル名を読めます。ファイルの本文はダミーで、読みません。
- duet-send はルーティング表を読んで、正しいセッションにメッセージを送ります。
- 送信そのものに失敗したとき（IDが古くなったときなど）は、Discord に知らせることもできます。

ビルドスクリプト、Discord ボット、定期実行のジョブ、手元の Claude Code などから Duet のコーディネーターに仕事を渡すために使えます。**macOS、Linux、Windows** で動きます。

```sh
bun run duet "夜間ビルドが終わりました。テストが3件落ちているので見てください。"
```

## なぜ作ったか

Claude Duet には、外からコーディネーターにメッセージを送る公式の経路（Webhook など）がありません。duet-send はその穴を今ある手段で埋めるツールです。公式の経路ができれば、このツールは不要になります。

> **非公式のツールです。** duet-send は個人が作ったもので、Anthropic・Google の製品ではなく、承認やサポートも受けていません。送信には Claude Code の公式ドキュメントにある機能（`claude -p --cloud` と hooks）だけを使いますが、それ以外は Claude Duet の現在（2026年後半）の動作に依存しており、予告なく変わることがあります。依存しているのは、コーディネーターが `--cloud` で届くクラウドセッションであること、交代するとセッションIDが変わること、コーディネーターが自分のIDを調べる方法、届いたメッセージに送信者の情報が付かないことです。duet-send が動かなくなったら、まずここを確認してください。

## かんたん導入（AIに任せる）

AI にこのリポジトリのリンクを渡して、次の順で導入を依頼してください。

1. **Claude Duet（メインのチャット）で**：「https://github.com/Stella2211/duet-send の duet-send を設定して」と頼みます。コーディネーターは [DUET_INSTRUCTIONS.md](DUET_INSTRUCTIONS.md) に沿って、Google ドライブに `duet-send` フォルダを作り、その中にルーティング表のファイルと、フォルダの説明を書いた短い README を置きます。Google ドライブに書く前に確認し、ファイルをリンクで共有する（閲覧者のみ）ようあなたに頼み、ファイルの Drive ID を教えます。1時間ごとに自分のIDを確認し直すための合図（定期実行）を作るかどうかも聞きます。
2. **手元のパソコンの Claude Code で**：「https://github.com/Stella2211/duet-send の duet-send を docs/setup-guide.ja.md に沿って入れて」と頼みます。足りないものを入れ、このリポジトリを取ってきて、`DUET_ROUTES_FILE_ID` を設定し（あなたの了承を得て）、送信のリハーサル（dry run）まで行います。

## 手で導入する

**まず、ルーティング表のファイルが必要です。** Duet のコーディネーターに設定を依頼してください（上の1）。コーディネーターがファイルを作成し、あなたがリンクで共有（閲覧者）すると、コーディネーターがそのファイルの Drive ID（ファイルのリンクの `/d/` の後ろの部分、または `id=` の値）を教えます。それまでは duet-send には読むものがありません。

必要なもの：

- [git](https://git-scm.com/downloads)（なければ、下のように ZIP でダウンロードしても構いません）
- [Bun](https://bun.com)
- ネイティブ版の [Claude Code](https://code.claude.com/docs/en/setup)（`claude auth login` でサインイン済み）

```sh
git clone https://github.com/Stella2211/duet-send.git
cd duet-send
export DUET_ROUTES_FILE_ID="<FILE_ID>"   # コーディネーターに教わった Drive ID（Windows は導入ガイドを参照）
bun run duet --dry-run "テスト"   # すべて確認するが、送らない
bun run duet "テスト"             # 実際に送る
```

git がない場合は、リポジトリのページで **Code → Download ZIP** を選び、展開したフォルダでターミナルを開いてください。

macOS、Linux、Windows それぞれの詳しい手順（定期実行やトラブルシューティングを含む）は [導入ガイド](docs/setup-guide.ja.md) にあります。0.2（gws を使う版）から更新する場合は [0.2（gws）からの移行](docs/setup-guide.ja.md#02gwsからの移行) を見てください。

## 使い方

```sh
bun run duet "メッセージ"
echo "長いメッセージ" | bun run duet
bun run duet --tag "[Discord bot]" "メッセージ"
bun run duet --to work "メッセージ"
bun run duet --dry-run "メッセージ"
bun run duet --verbose "メッセージ"
```

- `--dry-run` はセッションIDと `claude` を探し、送る内容を表示するだけで、送りません。失敗する場所は実際の送信と同じです。
- `--tag` はメッセージの先頭に付けるラベルです（既定は `[Claude Code]`）。この方法で送ったメッセージは送信者の情報なしで Duet に届くため、どのスクリプトから来たのかはタグで見分けます。
- `--to <ルート名>` は、ルーティング表の既定のルートではなく、そのルートに送ります。`DUET_ROUTES_FILE_ID` が必要で、`DUET_SESSION_ID` には切り替えません。ルーティング表のファイルを読めないときや、そのルートがないときは何も送りません。存在しないルートを指定すると、ファイルにあるルートの一覧を表示します。
- `--verbose` はセッションIDの全体と Claude Code 自身の出力を表示します。付けない場合は、ログやスクリーンショットに残らないよう ID を `session_01Ab…xyz` のように短縮して表示します。

別のフォルダや別のプログラムから呼ぶときは、スクリプトをフルパスで指定します。

```sh
bun /path/to/duet-send/send.ts --tag "[バックアップ]" "バックアップが終わりました"
```

任意で、duet-send を Claude Code の [Stop hook](https://code.claude.com/docs/ja/hooks#stop) として動かすこともできます（`send.ts --hook`）。手元の Claude Code が応答を終えるたびに、コーディネーターに知らせます。[導入ガイドの手順8](docs/setup-guide.ja.md#8-任意claude-code-が作業を終えたらコーディネーターに知らせるstop-hook) を見てください。

## セッションIDの読み込み先

ルーティング表は1行の JSON で、ルーティング表のファイルの **ファイル名** になっています。

```json
{"version":1,"updated_at":"2026-11-23T03:30:00Z","default":"main","routes":{"main":"session_..."}}
```

- `routes` はルート名からセッションIDへの対応です。`main` はコーディネーター自身です。ほかのルートを足すこともできます。
- `default` は、`--to` を付けないときに使うルート名です。
- `updated_at` は省略できます。`--dry-run` で表示するだけです。

duet-send は `https://drive.google.com/uc?export=download&id=<FILE_ID>` にサインインなしの通常の HTTPS でアクセスし、レスポンスの `Content-Disposition` ヘッダーからファイル名だけを読みます（本文は読みません）。ファイル名の最初の `{` から最後の `}` までをルーティング表の JSON として解釈するため、末尾に `.json` のような拡張子が付いていても問題ありません。ファイルがリンク共有になっていない場合、Google はサインインのページを返すため、duet-send はIDと「リンクを知っている全員」・閲覧者の設定を確認するよう伝えます。

Duet のチャットを複数使っている場合、各チャットのコーディネーターが同じルーティング表の中で自分のルートを更新します。各チャットで承認のルールを作っておくと、書き換えのたびに止まることはありません。[導入ガイドの手順9](docs/setup-guide.ja.md#9-任意ほかのチャットも自分のルートを更新する)を見てください。

`DUET_ROUTES_FILE_ID` がないときは `DUET_SESSION_ID` を使います。ルーティング表のファイルを読めない・解釈できないときも、`DUET_SESSION_ID` があれば、stderr に警告を出してそれを使います。`--to` を付けたときは切り替えません。存在しないルートや不正なルートは、必ず失敗します。

## 環境変数（すべて任意）

| 変数 | 役割 |
| --- | --- |
| `DUET_ROUTES_FILE_ID` | ルーティング表のファイルの Drive ID（ファイルのリンクの `/d/` の後ろの部分、または `id=` の値）。コーディネーターが教えてくれます。 |
| `DUET_SESSION_ID` | セッションIDそのもの。`DUET_ROUTES_FILE_ID` がないときに使い、ルーティング表のファイルを読めないときも代わりに使います（警告が出ます）。コーディネーターが変わると古くなります。 |
| `DUET_TAG` | メッセージの先頭に付ける既定のタグ。既定値は `[Claude Code]` です。`--hook` では使われず、hook のタグは `[Claude Code: Stop]` です。変えるときは `--tag` を使います。 |
| `DUET_DISCORD_WEBHOOK` | 送信そのもの（`claude -p ... --cloud`）に失敗したときに知らせる Discord の Webhook URL。IDが古い・アーカイブ済みのときや、Claude Code を起動できないとき（`claude` が見つからない、起動に失敗する）も対象です。通知されず stderr に出るだけなのは、ルーティング表のファイルを読めなかったとき、本文が長すぎるとき、hook の60秒タイムアウトです。通知の中のIDは短くして送ります。 |
| `DUET_CLAUDE_BIN` | `claude` のフルパス。Windows では `claude.exe` を指定します。定期実行では設定してください。 |
| `DUET_HOOK` | `1` のとき、`--hook` は何もしません。duet-send は自分が起動する `claude` にこれを付けるので、自分の送信で hook が動くことはありません。 |

## 補足

- ファイルのIDを知っている人は、ルート名とセッションIDを読めるうえ、あなたの Google アカウントの名前とメールアドレスも見えます（Google は共有ファイルの所有者を表示します）。ただし、ファイルの編集（閲覧者のみ）も、あなたのセッションへの送信（あなた自身の Claude サインインが必要）もできません。それでも ID は自分だけで持ち、コミットしないでください。ファイルを編集権限で共有してはいけません。編集できる人はファイル名を変更して、あなたのメッセージの宛先を変えられます。
- Windows では、npm が作る `claude.cmd` を使わずに止まります。`cmd.exe` を通すと本文が壊れたり、コマンドとして実行されたりするおそれがあるためです。ネイティブ版の `claude.exe` を入れてください。
- 本文は8,000文字までです。改行コードは `\n` にそろえ、タブ以外の制御文字は取り除きます。
- 送信はメッセージをキューに入れるだけで、コーディネーターの返事は待ちません。返事は Duet で確認してください。
